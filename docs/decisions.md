## 2026-10-31

### Зачем не «поиск готовых GIF»
На Trigger много редкого/нового. Готовых гифок мало → путь через YouTube.

### Продуктовый поток
1. Трек с Trigger (юзер залогинен).
2. Несколько YouTube-вариантов в UI.
3. Выбор → скачивание во **временное** хранилище → удалить после.
4. Кроп → превью → upload на **свой** Giphy (логин на сайте, не API key у каждого).
5. Ссылка в чат Trigger.

### Скачивание YouTube
Сначала **без native helper**. Результат spike: см. `spike-youtube-no-helper.md`.

### Giphy
Логин на сайте — чтобы было ок обычным юзерам (~5 человек).

### Аудитория / раздача
~5 человек, ручная установка. Git: папка + `.zip` → Load unpacked.

### Репо
GitHub **public**: `trigger-track-gif` (owner: ratmansky).

### Порядок этапов
Сначала **A (показать трек)** — сверка глазами. Потом B → C → D → E.

### Этап A — откуда берём трек
Источник правды на проде: **`GET /api/current_song_details`** (без логина).  
DOM (player-bar / landing) — запасной и для сверки «как на странице».  
Локальный клон `Trigger re-diz` для расширения **не** используем.

### Этап B — YouTube выдача
Смысл: не только «превью альбома» к треку, а **посмотреть на артиста**.  
Один фон.таб YouTube → несколько запросов, merge без дублей (~6–8):
`artist+title` (**трек**), `live performance` (**live**), `official video` (**клип**), `artist` (**артист**).  
Прямой fetch из popup → 403; поиск через скрытую вкладку + InnerTube.  
Клик = выбор → кроп в том же popup.

### Этап D — кроп
Всё в **popup**, без отдельной вкладки.  
~~YouTube iframe в расширении нельзя~~ → можно, см. 2026-11-01 «Интерактивный кроп».

## 2026-11-01

### Этап C — кадры без скачивания ролика
Не перехватываем `googlevideo` и не качаем файл. Открываем `youtube.com/watch?v=…&t=…` **активной** вкладкой (muted),
content script (isolated world) ждёт/пропускает рекламу, сикает на начало, играет отрезок и через
`requestVideoFrameCallback` рисует `<video>` в canvas (тот же origin → canvas не tainted).
12,5 fps, ширина 320 px, кодирование `gifenc` (MIT, `extension/vendor/`). 3 сек ≈ 38 кадров ≈ 0,8 МБ.
Вкладка именно активная: в фоне Chrome глушит видео-дорожку и таймеры.
Popup при этом закрывается → работой владеет service worker, результат в `chrome.storage.local`,
по готовности вкладка закрывается и popup открывается снова (`chrome.action.openPopup`).

### UI 0.7 — Figma-kit vibe
Popup: 8px сетка, ink primary (не purple), step rail 1–4, панели/кнопки primary·secondary·ghost.
Без отдельного Figma-файла — визуальный язык «стандартного UI kit», заточенный под узкий popup.

### Этап E — хостинг: catbox.moe (+ запасной pomf)
Giphy не даёт заливать «через логин на сайте», нужен API-ключ. Выбрали **catbox.moe**.  
С 2026 анонимный upload часто даёт **412 Invalid uploader** (edge / VPN / без userhash).  
Лечение в расширении: при 412 → запасной **pomf.lain.la** (прямая `.gif` ссылка).  
Опционально: `chrome.storage.local.catboxUserhash` — свой hash с catbox, тогда снова catbox.

### Этап E — в чат
«Вставить картинку» на Trigger = `prompt` с URL → URL уходит обычным сообщением; `MessageParser` рендерит
ссылки на `.gif/.png/…` как `<img>`. Расширение кладёт ссылку в `#message-input` и фокусирует вкладку Trigger;
«Отправить» жмёт человек (всегда смотрим глазами). Ссылка ещё и копируется в буфер — если вкладки Trigger нет.

### Интерактивный кроп — плеер прямо в popup
Error 153 = запрос embed-страницы без `Referer` (у страниц расширения его нет). Лечим session-правилом
`declarativeNetRequest`: ставим `Referer: https://triggerfm.online/` только для `youtube.com/embed/` во фреймах
**вне вкладок** (`tabIds: [-1]` = наш popup), обычный браузинг не трогаем.
`iframe_api.js` в MV3 грузить нельзя (remote script) → говорим его postMessage-протоколом (`enablejsapi=1`:
`listening` → `onReady` / `infoDelivery`, команды `seekTo` / `playVideo` / `mute`).
Превью гифки = плеер без контролов крутит **ровно** отрезок [начало, начало+длина) по кругу.
Управление — ползунки начала и конца (см. ниже), без кнопок.
Если ролик запрещает встраивание (error 101/150) или плеер молчит 12 с — запасной путь: цифры + «Превью на YouTube».

### Качество видео
Вкладка захвата: `movie_player.setPlaybackQualityRange('medium')` = **360p** (гифка 320 px — больше не нужно,
грузится быстрее, чем 720p+ по умолчанию). Не 144p — гифка будет мыльной.
Побочка: YouTube пишет выбор в `localStorage['yt-player-quality']` на год → сохраняем старое значение и
возвращаем перед закрытием вкладки.
Плеер в popup: качество через postMessage не управляется (`setPlaybackQuality` у YouTube no-op), но при
размере ~340×190 YouTube сам берёт низкое.

### Кроп: ползунки начало / конец, макс 6 сек
«Начало отсюда» — неудобно. Теперь `clip-slider.js`: тонкая полоска на весь ролик (двигает отрезок по песне) +
двойной ползунок начало/конец на окне 30 с вокруг отрезка (на всю песню 300 px = ~0,7 с/px — не попасть).
Длина 1–6 с: тянешь один край дальше лимита — второй едет следом. По умолчанию 30 с → 33 с.
Почему 6: 3 с ≈ 0,8 МБ → 6 с ≈ 1,6 МБ, быстро грузится в чате; дольше — уже клип, а не реакция.

### Error 152-4 во встроенном плеере
С `Referer: https://www.youtube.com/` после фикса 153 полезла 152-4 (без Referer тот же ролик даёт 153 —
проверено, т.е. заголовок доходит). Гипотеза: YouTube не принимает себя как embedder → ставим triggerfm.online.
Вторая возможная причина — ролик запрещает встраивание; тогда фолбэк: ползунки + «Превью на YouTube».
